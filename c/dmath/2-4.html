재귀적 알고리즘

점화 관계를 그대로 알고리즘으로 옮기면 자기 자신을 다시 부르는 재귀적 알고리즘이 됩니다. 재귀는 짧고 분명하지만, 같은 계산을 반복하면 매우 느려질 수 있고, 문제를 절반으로 줄이면 놀랄 만큼 빨라질 수 있습니다. 이 절에서는 호출 나무로 재귀의 비용을 세어 보고, 거듭제곱을 몇 번의 곱셈으로 줄일 수 있는지 도전합니다.

2.4.1

재귀로 피보나치 수를 구하면 왜 이렇게 느릴까?

재귀적 알고리즘 · 조작

  1. 질문"\(F(n) = F(n - 1) + F(n - 2)\), \(F(1) = F(2) = 1\)"을 그대로 컴퓨터 함수로 쓰면 아주 짧은 프로그램이 됩니다. 그런데 \(F(40)\)만 넣어도 한참 걸립니다. 무엇이 문제일까요?
  2. 복원수열의 귀납적 정의는 앞의 항으로 다음 항을 정합니다.
  3. 설명자기 자신을 더 작은 입력으로 다시 부르는 알고리즘을 재귀적 알고리즘이라 합니다. 재귀에는 ① 더 이상 부르지 않는 기저 경우(\(F(1), F(2)\))와 ② 문제를 줄이는 재귀 단계가 있어야 합니다. 피보나치를 그대로 재귀로 쓰면 \(F(n - 2)\)를 두 번, \(F(n - 3)\)을 세 번…처럼 같은 계산을 거듭해, 호출 횟수 \(c_n = c_{n-1} + c_{n-2} + 1\)이 \(F(n)\)처럼 기하급수로 늘어납니다. 한 번 구한 값을 기억해 두면(메모이제이션) 각 값을 한 번씩만 계산합니다.
  4. 연결하노이의 탑, 다음 카드의 빠른 거듭제곱, 병합 정렬처럼 재귀가 잘 맞는 문제도 많습니다. 호출 횟수를 점화식으로 세우는 것이 알고리즘의 효율을 따지는 기본 방법입니다.
  5. 적용\(n\)을 늘리며 호출 나무가 얼마나 빨리 커지는지 보세요. 같은 색 마디가 몇 번 나오나요? "기억하기"를 켜면 나무가 어떻게 바뀌나요? 아래에서 \(n = 30, 40\)일 때 호출 횟수를 비교하세요.
  6. 판단기저 경우가 없거나 입력이 줄지 않으면 재귀는 끝나지 않습니다. 또 짧고 아름다운 코드가 빠른 코드는 아닙니다. 정의를 그대로 옮기기 전에 같은 계산이 반복되는지 따져 보세요.

2.4.2

a¹⁰⁰을 곱셈 몇 번 만에 구할 수 있을까?

분할 정복 재귀 · 도전

지금 가진 것: a¹

  1. 질문\(a^{100}\)을 \(a \times a \times \cdots\)로 구하면 곱셈이 99번 필요합니다. 그런데 \(a^{100} = (a^{50})^2\)이고 \(a^{50} = (a^{25})^2\)입니다. 이렇게 하면 곱셈을 얼마나 줄일 수 있을까요?
  2. 복원\(a^{m}\cdot a^{n} = a^{m+n}\), \((a^m)^2 = a^{2m}\)입니다.
  3. 설명재귀적 알고리즘 \(\mathrm{pow}(a, n)\): \(n = 0\)이면 1, \(n\)이 짝수이면 \(\mathrm{pow}(a, n/2)^2\), 홀수이면 \(a \cdot \mathrm{pow}(a, n - 1)\). 문제를 절반 크기로 줄이므로(분할 정복) 곱셈 횟수는 \(n\)의 이진법 자릿수와 1의 개수 정도, 약 \(2\log_2 n\)번 이하입니다. \(n = 100\)이면 8번, \(n = 1000\)이면 14번이면 됩니다.
  4. 연결인터넷 보안의 RSA 암호는 수백 자리 수의 거듭제곱을 나머지 계산으로 하는데, 이 빠른 거듭제곱 없이는 불가능합니다. 고급 대수에서 본 행렬의 거듭제곱 \(A^n\)에도 그대로 쓸 수 있습니다.
  5. 적용"제곱하기"와 "a 곱하기"만으로 목표 지수에 정확히 도착해 보세요. 곱셈 횟수가 재귀 알고리즘보다 적거나 같으면 성공입니다. 목표를 이진법으로 쓰면 어떤 규칙이 보이나요?
  6. 판단재귀 알고리즘이 늘 가장 적은 곱셈을 쓰는 것은 아닙니다. 예를 들어 \(a^{15}\)는 재귀로 6번이지만, \(a^3\)을 먼저 만든 뒤 \((a^3)^5\)를 계산하는 등 다른 길로 5번에 할 수 있습니다. "충분히 빠른 방법"과 "가장 빠른 방법"은 다른 문제입니다.
